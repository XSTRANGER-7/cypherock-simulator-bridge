How it works

Only the USB cable is swapped

The SDK, its packets and the firmware's own code all run for real. The bridge carries the same 64-byte frames that would travel over USB.

Your app or test Cypherock SDK: app-manager, app-evm, app-btc… and sdk-core
64-byte frames
The bridge @cypherock/sdk-hw-simulator over TCP 127.0.0.1:52640 WasmDeviceConnection: frames go straight into the firmware's memory
same packets as USB
X1 firmware The firmware's simulator build (SDL2), with a socket frame server The same C firmware compiled to WebAssembly with Emscripten, in this tab
  1. 1The SDK builds the exact packets it would send over USB: header, CRC-16, chunks, protobuf payload.
  2. 2The transport sends them as 64-byte frames to a socket that only listens on localhost.The transport hands the 64-byte frames to the firmware inside the same tab. No server, a private device per tab.
  3. 3The firmware polls for frames in BSP_DelayMs() every 5 ms, as the USB interrupt would, and its own parser, apps and UI answer.
Features

Everything a hardware-wallet developer needs, minus the hardware

Real firmware, not a mock

The X1 firmware's own C code answers every call: comm layer, app handlers and on-screen UI.

Unchanged SDK code

DeviceConnection from @cypherock/sdk-hw-simulator drops in where the USB transport goes. App code stays the same.

Hands-free in CI

Built with DEV_SWITCH=ON, the firmware confirms its own screens, so tests never wait for a button press.

Deterministic test wallet

A SIMTEST wallet from a published test mnemonic. Addresses and signatures are checked against ethers and viem.

See every packet

A live wire and a decoded packet feed: STATUS polls, commands, acks and results, colour-coded as they happen.

Runs anywhere

Ubuntu (or WSL2), Windows with MSYS2, one Docker command, or no install at all: the browser build.

Quick start

Up and running in minutes

Nothing to install. The firmware boots inside your tab; every visitor gets a private device.

Open X1 Quest

Builds the upstream firmware and SDK with the patches (about 15 minutes), then serves the playground.

git clone https://github.com/XSTRANGER-7/cypherock-simulator-bridge
cd cypherock-simulator-bridge
docker build -t x1-sim-playground -f docker/Dockerfile .
docker run --rm -p 127.0.0.1:3000:3000 x1-sim-playground
# open http://127.0.0.1:3000

Swap the USB transport for the simulator one. Everything after that is ordinary SDK code.

import { DeviceConnection } from '@cypherock/sdk-hw-simulator';
import { ManagerApp } from '@cypherock/sdk-app-manager';

const connection = await DeviceConnection.create();   // TCP 127.0.0.1:52640, not USB
const manager = await ManagerApp.create(connection);  // unchanged SDK code
console.log(await manager.getDeviceInfo());           // answered by real firmware code

Ubuntu 22.04 or Windows with MSYS2. Full steps, including the SDK build: docs/setup.md.

./scripts/build-simulator.sh          # the X1 firmware simulator, with the bridge patch
npm ci
npm run playground:web                # http://127.0.0.1:3000
npx tsx examples/get-eth-address.ts   # address from the firmware, checked with ethers

Two upstream firmware bugs found and fixed

Building this turned up a stack buffer overflow in the simulator's flash emulation (it aborts at boot with stack smashing detected) and missing includes in mpz_ecdsa.c that newer GCC and Clang reject. Both fixes are small, separate branches.

Safe by design

  • Test mnemonic only: never type a real seed into a simulator.
  • The bridge listens on 127.0.0.1 only.
  • Signatures are verified, never broadcast.

FAQ

Good questions

Is this an official Cypherock product?

No. It is an independent open-source project built on Cypherock's open-source firmware (x1_wallet_firmware) and SDK. It is not affiliated with or endorsed by Cypherock.

Do I need an X1 Vault?

No. The simulator is the firmware itself, built for a PC (or for WebAssembly). Developers can try every supported SDK call before they own the hardware, and CI can run them on every push.

What does not work yet?

X1 card flows: the simulator's card emulation speaks an older plaintext protocol while the firmware encrypts card commands, so a test-mnemonic wallet is used instead. selectWallet waits for a joystick choice, device and card authentication need Cypherock's server, and firmware updates need a bootloader. Details are in docs/limitations.md.

How is the browser version built?

GitHub Actions compiles the upstream firmware plus a small patch to WebAssembly with Emscripten, bundles the SDK for the browser with esbuild, plays all 11 levels in headless Chrome, and only then publishes to GitHub Pages. See docs/deploy.md.

Is anything sent to a server when I play?

No. The firmware and the SDK both run inside your tab, and the wallet comes from a published test mnemonic. Your progress (XP and levels) is saved only in your browser.
